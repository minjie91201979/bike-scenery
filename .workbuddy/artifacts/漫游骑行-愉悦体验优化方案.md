# 漫游骑行 Scenery Ride · 愉悦体验优化方案

> 版本 v1.0 · 仅诊断与建议，不含代码改动
> 角色：愉悦体验设计师（Whimsy Injector）
> 结论先行：**产品缺的不是功能，是「反馈 — 奖励 — 沉淀」的闭环。**
> 每一个功能点都做到了"能用"，但几乎没有一个做到"值得回味"。

---

## 一、现状盘点：功能完备度 vs 体验浓度

先把现有的功能资产列一遍，看看"料"有多足：

| 能力 | 现状 | 体验浓度 |
|---|---|---|
| 17 国地球选单（Three.js 可拖拽自转球体） | 已完成，含射线拾取、自转、标签精灵 | 中（视觉有，交互反馈弱） |
| 16 套场景包 × 各国地标简模（200+ LandmarkKind） | 已完成，体量惊人 | 高（内容）／低（呈现） |
| 3 视角（跟随/电影/第一人称）+ 鼠标自由环视 | 已完成 | 中 |
| 3 时段（白天/黄昏/夜晚） | 已完成，但瞬时切换 | 低 |
| 6 景点/场景 + 民族服饰迎宾 NPC | 已完成，含 56 民族配色映射 | 内容高／反馈低 |
| 野生动物碰撞（含脾气/无敌帧） | 已完成 | 中（负反馈只有文字） |
| 拍照下载（F） | 已完成 | 低（几乎无反馈） |
| 小地图、速度表、里程、用时 | 已完成 | 中（纯数据，无情绪） |
| 移动端虚拟按键（左右 + 油门/刹车） | 已完成 | 中 |

**判断：内容侧已经严重"超配"，反馈侧严重"欠配"。** 这是一件好事——意味着不需要再堆功能，只需要把已有功能"接通情绪"。

## 二、诊断出的 12 个情绪断点（按严重度排序）

### 🔴 S 级：直接决定"惊艳与否"

**1. 全程静音 —— 最大的单项失分项**
仓库里没有任何音频资源引用。一个以"风景"为核心卖点的产品，没有风声、鸟鸣、车轮滚动、快门声、环境音乐。
> 经验值：环境音对沉浸感的贡献通常超过任何视觉特效，而成本只有视觉特效的 1/10。

**2. 所有反馈都被压扁成同一个 1.9 秒 toast**
`App.tsx` 里只有一个 `showToast`，1900ms 自动消失，全局单例。
于是"发现新景点""被老虎扑了""照片已保存""国家开发中"这四种**情绪等级完全不同的事件**，用了**完全一样**的表现：底部一条居中文字。
- 信息层级扁平 → 用户分不清什么值得高兴
- 单例互相顶掉 → 连续发现两个景点，第一个直接被吞
- 无图标/无音效/无动效 → 没有"事件感"

**3. 车永远停不下来，与品牌承诺自相矛盾**
`constants.ts`：`CRUISE=6.4` / `BRAKE_MIN=2.0`。松开所有键自动回到 6.4 m/s，按住 S 也只能降到 2.0 m/s。
而 `StartScreen` 的文案写的是：**"不必赶路，慢一点，风景才看得清。"**
> 文案承诺了"可以慢"，交互却不允许"停"。这是产品人格的裂缝，用户会本能地感到"说一套做一套"。

**4. 拍照没有仪式感，且大概率在移动端静默失败**
`canvas.toBlob` → `a.click()` 下载 → toast「照片已保存到下载目录」。
- 没有快门动画、没有闪光灯、没有声音 → 用户不确定到底拍没拍
- 没有"相册" → 拍完即消失，作品无沉淀
- Android WebView / iOS 对程序化下载限制严格，很多情况下文件根本没落盘，而 UI 依然报成功

**5. 投入零沉淀 —— 退出即清零**
`seen: Set<number>` 只活在 `RideEngine` 内存里。切场景、刷新、关页面，全部归零。
没有护照、没有累计里程、没有国家进度、没有成就。用户花 10 分钟骑完一圈，什么都没留下。

### 🟠 A 级：体验明显"糙"

**6. 出发没有仪式**：点「开始漫游」→ 直接硬切进 HUD。没有镜头推入、没有倒计时、没有第一声风。
**7. 地球选国没有发现感**：无 hover 高亮态、无国家卡片、无"你已发现 3/6 景点"的进度回显。锁定的 toast（「开发中，敬请期待」）在 17 国全开的情况下已成死代码。
**8. 景点打卡是一次性文字**：`greeterWelcomeMessage` 生成的「「汉族」欢迎你来到北京·天安门！」——这是全产品最有潜力的彩蛋点（民族服饰 + 地标 + 一句问候），却只用了一条 toast 表达。
**9. 碰撞只有惩罚没有补偿**：速度被压到 `BRAKE_MIN*0.55`，2.4 秒无敌帧，一条「被兔子撞到了」。没有画面反馈（震动/闪红）、没有声音、没有任何补偿。纯负向。
**10. 时段切换是硬切**：`sky.setTimeOfDay()` 瞬时改参数，没有 1~2 秒的日照补间，也没有配套的天文事件。
**11. 首次引导是一整面文字墙**：HUD 左下 6 行按键说明，移动端还被折叠。没有分步、没有"现在试试按 W"的交互式教学。
**12. 无障碍基本空白**：`#touch-controls` 标了 `aria-hidden="true"`；CSS 里没有 `:focus-visible`、没有 `prefers-reduced-motion`；按钮只有 `class="active"` 没有 `aria-pressed`；景点发现没有 `aria-live` 播报。

### 附带发现（技术侧，供参考）
- `StartScreen` 里的 `#loading` 元素是**静态文本**「React 18 · TypeScript · Three.js」，名不副实——它本该是加载提示位，却被技术栈招牌占了。
- 速度条上限硬编码 `65`（`Hud.tsx`），与 `SPRINT=16.8 m/s ≈ 60.5 km/h` 不一致，进度条永远填不满。
- 小地图在触屏折叠态默认不可见，而移动端恰恰最需要"我在哪"。

## 三、品牌人格定位：先定调，再谈 whimsy

**这套产品的文案已经在说话了**：「不必赶路，慢一点，风景才看得清」「已选择中国…挑选骑手后即可上路」。
它的声音是**沉静、克制、温和的旅伴**，不是喧闹的派对主持人。

| 维度 | 我们的定位 | 反面（**明确不要做**） |
|---|---|---|
| 人格 | 沉静的旅伴 / 会陪你发呆的朋友 | 热情客服、话痨吉祥物 |
| 情绪密度 | 低频高质：一次骑行 3~5 个"啊"的瞬间 | 高频撒花、每 10 秒一个提示 |
| 视觉语言 | 微光、风、落叶、涟漪、远处的钟声 | emoji 雨、彩带爆炸、霓虹渐变 |
| 奖励方式 | 印章、明信片、护照、一句话 | 弹窗、进度条、每日签到、体力值 |
| 幽默 | 藏在细节里（"它只是想打个招呼"） | 网络梗、双关、卖萌台词 |

> **最重要的一条原则：不要给这个产品加 emoji 撒花。**
> 那会瞬间摧毁它辛苦建立的治愈气质。所有庆祝应该是"世界回应了你"，而不是"UI 恭喜了你"。

## 四、三层反馈系统（替代单一 toast）

这是整个方案的地基，建议最先做。

| 层级 | 用途 | 位置 / 时长 | 表现 | 典型场景 |
|---|---|---|---|---|
| **L1 低语 Whisper** | 轻提示，不打断 | 左下角淡入淡出，1.2s | 小字 + 极轻的位移 | 视角已切换 / 时段已切换 / 已全屏 |
| **L2 时刻 Moment** | 值得记住的事 | 居中偏下卡片，2.8s | 图标 + 标题 + 一句文案 + 微光 | 景点打卡 / 拍照成功 / 里程里程碑 |
| **L3 庆典 Celebration** | 稀有成就 | 全屏 0.6s 柔光 + 卡片 4s | 金色微光 + 短旋律 + 卡片 | 环线完成 / 国家集齐 / 隐藏彩蛋 |

**配套规则**
- 三条通道**互不顶掉**，L2/L3 走队列（最多同时 2 条，超出排队）
- 全部走 `aria-live="polite"`，屏幕阅读器可播报
- `prefers-reduced-motion` 下 L3 降级为静态卡片（去掉柔光与位移）
- 音效与反馈层级绑定：L1 无音 / L2 单音 / L3 三音短旋律

## 五、分阶段建议清单

### P0 · 立刻见效（预计 1~2 天，投入产出比最高）

| # | 建议 | 为什么它值 | 涉及文件 |
|---|---|---|---|
| P0-1 | **加音频骨架**：1 条环境音（按时段/场景切换）+ 1 组互动音（快门/打卡/碰撞）+ 1 段主题旋律（进入骑行淡入） | 静音是最大失分项 | 新增 `src/audio/` |

| P0-3 | **真正的"停下来"**：长按 S/空格可减速到 0，停下触发「驻足模式」（相机缓慢环绕 + 环境音放大 + POI 卡片展开 + "按 W 继续"） | 兑现品牌承诺，也是拍照的最佳时机 | `constants.ts` / `RideEngine.ts` |
| P0-4 | **拍照仪式感**：白闪 + 快门音 + 画面四边短暂收拢黑框 + 右下角"相册"角标（缩略图堆叠，可点开回看） | 把"下载文件"变成"留下作品" | `RideEngine.screenshot()` |

| P0-6 | **出发仪式**：镜头从天空俯冲落地 → 3-2-1 倒计时 → 第一声风与脚踏 | 把"点击开始"变成"启程" | `StartScreen.tsx` / `RideEngine.ts` |

### P1 · 一周内（建立留存与收集闭环）

| # | 建议 | 说明 |
|---|---|---|
| P1-1 | **旅行护照**（localStorage）：国家印章 + 景点打卡页 + 累计里程 + 访问日期。地球界面与开始页可回看 | 让投入有沉淀，是复访的第一动力 |
| P1-2 | **地球选国层的发现感**：hover 高亮 + 国家卡片（旗帜色 / 一句话 / 已解锁 x/6）+ 点击后镜头推近该国再切换 | 从"点图标"变成"在地球旅行" |
| P1-3 | **温柔惩罚**：碰撞加震动 + 画面微暗 + 动物叫声 + **补偿**（掉落一片羽毛/一颗果实，进入背包），文案改「它只是想打个招呼。」 | 把纯负反馈变成一段小故事 |
| P1-4 | **成就系统（低强度）**：夜游者 / 慢行者（2 分钟不加速）/ 动物之友（遇 5 种动物）/ 环线完成 / 环球旅人 | 解锁用 L3 柔光，不用 emoji 雨 |
| P1-5 | **时段渐变 + 天文彩蛋**：1.5s 日照补间；夜晚随机流星（点击许愿）→ 黄昏鸟群归巢 → 白天蝴蝶 | 让"切换时段"变成"值得等"的事 |
| P1-6 | **触屏质感**：油门按下时波纹扩散 + 阻尼感；Capacitor Haptics 在打卡/碰撞/拍照时震动；可选陀螺仪轻转向 | 移动端是主战场之一 |
| P1-7 | **无障碍补齐**：`:focus-visible` 焦点环、`aria-pressed`、`prefers-reduced-motion` 降级、`aria-live` 播报、移除 `aria-hidden` 误用 | 愉悦≠排斥， inclusivity 是硬指标 |

### P2 · 品牌层（长期记忆点与传播）

| # | 建议 | 说明 |
|---|---|---|
| P2-1 | **明信片分享**：拍照后合成带邮戳 / 地点名 / 日期 / 一句文案的明信片，可保存可分享 | 唯一的社交传播点，值得重投 |
| P2-2 | **天气与季节**：细雨 + 车辙水花 / 秋叶飘落 / 俄罗斯飘雪，可随真实日期变化 | 让"再来一次"有理由 |
| P2-3 | **隐藏彩蛋**：Konami 码 → 星空道路；某 POI 停留 60 秒 → 隐藏观星点；连续骑行 10 分钟 → 骑手回头挥手 | 探索型彩蛋，社群讨论的燃料 |
| P2-4 | **骑手人格化**：路过动物时侧头看、到景点时回头笑、停下时哼歌 | 角色陪伴感，成本不高情绪很足 |
| P2-5 | **慢直播模式**：无操作 30 秒后自动进入——UI 全隐、相机缓慢环绕、只留环境音 | 把游戏变成屏保，延长停留时长 |

## 六、中文愉悦文案库（治愈系，可直接用）

**加载 / 启动**
- 「正在为你铺开一条路…」
- 「正在唤醒这片土地的清晨…」
- 「路已经铺好了，剩下的交给你。」

**出发**
- 倒计时 3 → 2 → 1 →「出发。」（不加感叹号）

**驻足（停下来）**
- 「你停下来了。风声、鸟鸣，都在等你。」
- 「这里不错，多待一会儿也没关系。」
- 「按 W 继续，或者就这么坐着。」

**拍照**
- 「咔嚓 —— 这一刻被你留下了。」
- 「明信片已收进相册，随时可以回看。」（替代"已保存到下载目录"）

**景点打卡**
- 「第 3 站 · 西湖 · 你来得正是时候。」
- 「「白族」欢迎你来到云南·大理！（这是今天的第一位朋友）」
- 「6 站已走完 4 站，剩下的路还长。」

**碰撞（负反馈转正）**
- 「它只是想打个招呼。」
- 「慢一点，就撞不到了 —— 不过它好像并不在意。」
- 「捡到一片羽毛。算它的赔礼。」

**时段切换**
- 白天 →「天亮了，路看得更清楚了。」
- 黄昏 →「太阳要落了，这一段最好看。」
- 夜晚 →「天黑了，路灯会替你照亮前面。」

**里程碑 / 成就**
- 1km →「第一公里。不着急，还有很远。」
- 环线完成 →「一圈结束了。要不要再来一圈，看看刚才错过的？」
- 夜游者 →「原来夜晚的路上，还有别人在唱歌。」
- 慢行者 →「你骑得很慢，看得最多。」

**空状态 / 异常**
- 无网络（若未来加榜单）→「信号走丢了，风景还在。」
- 加载失败 →「这条路被雾遮住了，换个国家试试？」
- 未开放国家 →「这一站还在修路，先去中心看看？」（替换现有的「开发中，敬请期待」）

## 七、反模式清单：明确不要做的事

| ❌ 不要 | 原因 |
|---|---|
| emoji 撒花、彩带爆炸、霓虹渐变 | 摧毁治愈气质，与产品人格冲突 |
| 强制弹窗 / modal 打断骑行 | 用户是来放松的，任何阻断都是冒犯 |
| 每日签到、体力值、连胜 | 把"治愈"变成"上班"，直接劝退核心用户 |
| 自动播放 BGM 且不给开关 | 移动端大忌，且侵犯控制权 |
| UI 占据屏幕 > 20% | 风景才是主角 |
| 每个动作都给奖励 | 奖励通货膨胀 = 没有奖励 |
| 用"恭喜你！"这种客服腔 | 品牌声音是旅伴，不是商场广播 |

## 八、成功度量（建议埋点）

| 指标 | 现状基线（需埋点） | 目标 |
|---|---|---|
| 单次会话时长 | — | +40% |
| 平均骑行里程 | — | +25% |
| 景点完成率（seen/total） | — | 中位数 ≥ 60% |
| 拍照触发率 | — | ≥ 1 次/会话 |
| 成就解锁后次日回访率 | — | +30% |
| **"未被顶掉"的正反馈占比** | 目前约 0%（单例互顶） | ≥ 95% |
| 移动端崩溃/卡顿反馈 | — | 下降 |

其中最后一条是最直接的判據：**如果用户的正反馈还会被系统自己吞掉，就谈不上愉悦。**

## 九、如果只做一件事

> **把「发现景点」这一件事做到极致。**

它是这个产品的灵魂交汇点：民族服饰 NPC + 地标 + 一句问候 + 一次打卡 + 一张照片。
把 L2 打卡卡片 + 音效 + 护照印章 + 拍照四个动作串成一个 3 秒的完整体验，用户就会记住"我在漫游骑行里到了一个地方"。

其余所有建议，都是在复制这个模式的成功。
