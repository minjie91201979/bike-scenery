# 2026-09-10

## 愉悦体验设计诊断（不改代码，仅方案）

- 主人要求：分析 bike-scenery（漫游骑行 Scenery Ride）游戏体验，只给优化方向与建议，不动代码。
- 产出：`.workbuddy/artifacts/漫游骑行-愉悦体验优化方案.md`

### 关键结论
- 核心判断：**内容侧严重超配，反馈侧严重欠配**。缺的不是功能，是「反馈—奖励—沉淀」闭环。
- 最大失分项：全程静音（无任何音频资源）、所有反馈压扁成单条 1.9s toast（App.tsx `showToast`，单例互顶）。
- 品牌人格裂缝：文案承诺「不必赶路，慢一点」，但 `CRUISE=6.4` / `BRAKE_MIN=2.0` 导致车永远停不下来。
- 投入零沉淀：`RideEngine.seen: Set<number>` 仅内存，退出清零，无护照/成就/持久化。

### 方案骨架（供后续实施参考）
- 三层反馈系统：L1 低语(1.2s 无音) / L2 时刻(2.8s 单音) / L3 庆典(4s 三音)，互不顶掉 + aria-live。
- P0 六项：音频骨架、三层反馈、真正能停下(驻足模式)、拍照仪式感+相册、景点打卡卡+护照、出发仪式。
- P1 七项：旅行护照、地球选国发现感、碰撞温柔惩罚+补偿、低强度成就、时段渐变+天文彩蛋、触屏质感、无障碍补齐。
- P2 五项：明信片分享、天气季节、隐藏彩蛋(Konami→星空道路)、骑手人格化、慢直播模式。
- 品牌调性定为「沉静的旅伴」，**明确禁止 emoji 撒花/彩带/签到体力**——会摧毁治愈气质。
